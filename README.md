# Tura river flood at Tyumen, July 2026

Satellite flood-mapping analysis for the RGS Young Geographer of the Year
(KS5, "From Source to Sea") project, and the accompanying report
`report/tura_flood_report.pdf`.

**Research question.** Tyumen was founded in 1586 on the high southern
bank of the Tura; the northern bank is low and historically unprotected.
Does that siting decision still determine which side of the river floods,
and does the July 2026 record flood (891 cm, a level that reached the
previously-unflooded "second tier") show that the old siting logic only
holds up to a threshold?

Full write-up, method, figures and discussion: **`report/tura_flood_report.pdf`**.

## Reproducing the raw data

The `data/raw/` folder is not committed (large binary files, and it is fully
reproducible). To rebuild it:

1. **Sentinel-2**: in the Copernicus Browser, search tile T41VPD / Tyumen for
   18 June 2026 and 29 July 2026, and export bands B02/B03/B04/B11 (Analytical
   download) to `data/raw/s2_20260618/` and `data/raw/s2_20260729/` respectively.
2. **DEM**: download
   `https://copernicus-dem-30m.s3.amazonaws.com/Copernicus_DSM_COG_10_N57_00_E065_00_DEM/Copernicus_DSM_COG_10_N57_00_E065_00_DEM.tif`
   to `data/raw/Copernicus_DSM_COG_10_N57_00_E065_00_DEM.tif` (public, unauthenticated).
3. **OSM**: `curl "https://overpass-api.de/api/map?bbox=65.50,57.14,65.56,57.17" -o data/raw/osm_tyumen_extract.osm`

## Method summary

1. `scripts/dem_water_mask.py` — computes MNDWI = (B3−B11)/(B3+B11) for both
   dates, reprojects the DEM onto the Sentinel-2 grid, and derives a
   DEM-constrained water mask (spectral threshold + elevation cut-off +
   connectivity to a high-confidence seed) to remove cloud-shadow and
   dark-rooftop false positives that a pure spectral threshold picks up in
   this urban scene.
2. `scripts/polygonize_and_exposure.py` — polygonises the masks, derives a
   north/south dividing line from the local river tangent (calibrated
   against the known south-bank location of the Tyumen kremlin), and counts
   flooded buildings, roads and (via the WorldPop API) population on each
   bank.
3. `scripts/make_figures.py`, `scripts/make_fig2_cross_section.py`,
   `scripts/make_fig3_exposure.py` — produce the three report figures.
4. `scripts/build_qgis_project.py` — writes `qgis/tura_flood_tyumen.qgs`
   referencing the processed vector and raster layers.

Run in order after reproducing the raw data (`data/raw/`); each script reads
from and writes to `data/processed/` and (for figures) `figures/`.

## Requirements

Python 3, with `rasterio`, `geopandas` (pyogrio backend), `shapely`,
`scipy`, `matplotlib`, `numpy`. Report built with `pandoc` (xelatex engine,
for Cyrillic text support).

## Limitations

See `report/tura_flood_report.pdf` §Limitations — in brief: 10–20 m pixel
size, single-overpass snapshot two days before the observed peak (likely a
conservative/lower-bound flood extent), and residual under/over-counting
from cloud shadow and the DEM-connectivity approximation (~3–4% area
change from the geometry simplification used for the WorldPop query).
